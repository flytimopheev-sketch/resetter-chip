# Участие в разработке

Спасибо за интерес к **Resetter Chip**! Ниже — как предложить изменение,
сообщить об ошибке и что ожидается от pull request.

## Сообщения об ошибках и идеи

- Проверьте, нет ли уже похожего issue в трекере.
- Используйте шаблоны: [bug report](.github/ISSUE_TEMPLATE/bug_report.yml) и
  [feature request](.github/ISSUE_TEMPLATE/feature_request.yml).
- Для ошибок приложите версию ОС, версию Qt, модель программатора и чипа,
  шаги воспроизведения и фрагмент лога
  (`~/.local/share/ResetterChip/Resetter Chip/logs/Resetter-chip.log`).
- **Не прикладывайте дампы картриджей с персональными или служебными данными**,
  заменяйте значения на условные.

## Pull request

1. Форкните репозиторий и создайте ветку от `main`:
   `feature/краткое-название` или `fix/краткое-название`.
2. Соберите проект и прогоните тесты:

   ```bash
   cmake -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTS=ON
   cmake --build build -j"$(nproc)"
   ctest --test-dir build --output-on-failure
   ```

3. Добавьте тесты на новую логику (`tests/`, Qt Test).
4. Обновите `README.md` и `CHANGELOG.md`, если изменилось поведение.
5. Убедитесь, что код собирается без новых предупреждений.
6. Откройте PR и опишите: что изменено, зачем и как проверялось.

CI прогоняет сборку и тесты в контейнере Fedora 40 — PR должен быть зелёным.

## Стиль кода

- C++17, Qt 6, `QStringLiteral` для строк, 4 пробела, LF, UTF-8.
- Имена: классы `CamelCase`, методы `camelCase`, поля `m_` + `camelCase`.
- Логика — в `src/core` и `src/adapters` без зависимости от GUI.
- Не использовать `unwrap`-подобные конструкции и игнорирование ошибок:
  возвращайте `std::optional`/коды ошибок и логируйте причину.
- Все пользовательские строки — на русском, через `QStringLiteral`.
- Не добавлять зависимости без обсуждения в issue.

## Коммиты

Используется [Conventional Commits](https://www.conventionalcommits.org/ru/):

```
feat(core): поддержка 24C1024 в профилях
fix(adapter): корректный STOP при NAK
docs(readme): описание формата дампа
test(validation): границы защищённых диапазонов
```

## Как добавить профиль картриджа

1. Создайте JSON-файл в `src/profiles/` (или добавьте запись в существующий).
2. Укажите `id`, `name`, `size_bytes`, адресацию и `counter_offset`.
3. Проверьте защищённые диапазоны — они не должны пересекаться.
4. Добавьте тест, если профиль меняет поведение по умолчанию.

Формат описан в [docs/PROFILES.md](docs/PROFILES.md).
