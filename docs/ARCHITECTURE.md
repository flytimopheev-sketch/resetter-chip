# Архитектура

## Обзор

Приложение разделено на независимое ядро и графический интерфейс.
Ядро (`Resetter_core`) собирается как статическая библиотека и не зависит
от QtWidgets, поэтому его можно использовать в тестах и консольных утилитах.

```
┌──────────────────────────────────────────────────────────────┐
│ gui/         MainWindow, ConnectionPanel, CartridgePanel,    │
│              OperationsPanel, HexEditor, LogPanel, StatusBar │
└───────────────▲───────────────────────────┬──────────────────┘
                │ сигналы/слоты Qt          │ запросы операций
┌───────────────┴───────────────────────────▼──────────────────┐
│ core/        ChipWorker (рабочий поток), ProfileManager,     │
│              DumpManager, CounterReset, Validator, Checksum  │
└───────────────▲───────────────────────────┬──────────────────┘
                │ ChipParams                │ read/write/scan
┌───────────────┴───────────────────────────▼──────────────────┐
│ adapters/    AdapterFactory, IChipAdapter, Ch341AI2cAdapter  │
│              (libusb-1.0, протокол CH341A I2C)               │
└──────────────────────────────────────────────────────────────┘
```

## Потоки выполнения

- **GUI-поток** — все виджеты, HEX-редактор и журнал.
- **Рабочий поток** — `ChipWorker`, созданный в `MainWindow::setupWorker()`
  и перенесённый в `QThread`. Длительные операции (чтение, запись,
  верификация, сканирование) выполняются здесь.
- Обмен результатами — через сигналы `operationResult`, `operationProgress`,
  `operationFinished` с `Qt::QueuedConnection`.
- Отмена — атомарный флаг `ChipWorker::cancel()`, безопасный из GUI-потока.

## Профили

`ProfileManager` — синглтон, загружающий `*.json` из каталога профилей.
Каталог ищется в порядке:

1. переменная окружения `Resetter_CHIP_PROFILES`;
2. `./profiles` рядом с исполняемым файлом;
3. `../share/Resetter-chip/profiles` (установка из `build/`);
4. исходники (`../src/profiles`, `../../src/profiles`);
5. `/usr/share/Resetter-chip/profiles`, `/usr/local/share/...`.

Один файл может содержать как массив профилей, так и одиночный объект.
Профили с пустым `id` или нулевым `size_bytes` игнорируются.

## Контейнер дампа

`DumpManager` сохраняет данные в собственный формат `RSCHIPD1`:

```
+--------+----------------+------------------+-----------+-------+
| 8 байт |  quint16       |  QString id      |  QString  | QDate |...
| magic  |  версия = 1    |  чипа            |  картридж | время |
+--------+----------------+------------------+-----------+-------+
| quint32 размер | quint32 CRC32 |  данные (raw)                    |
+---------------------------------------------------------------+
```

Метаданные пишутся через `QDataStream` версии `Qt_6_0`. При загрузке:

- файл с магией разбирается как контейнер;
- файл без магии считается «сырым» бинарным дампом `.bin`;
- CRC32 файла проверяется заново и попадает в `DumpInfo`.

## Сброс счётчика

`CounterReset` работает только с дампом в памяти:

- `readCounter()` — читает `counterSize` байт (1, 2 или 4) по `counterOffset`;
- `resetCounter()` — возвращает копию дампа с обнулённым счётчиком;
- `setCounter()` — записывает произвольное значение с проверкой границ.

Смещение `0xFFFFFFFF` означает, что счётчик для профиля не задан.

## Валидация перед записью

`Validator::validateBeforeWrite()` проверяет:

1. размер дампа совпадает с `size_bytes` профиля;
2. изменения не затрагивают `protected_ranges` (пары `[start, end)`);
3. изменённые байты лежат в разрешённых диапазонах (если они переданы).

При нарушении запись блокируется, а причина попадает в журнал.

## Запись и верификация

`Ch341AI2cAdapter::write()` разбивает данные по страницам профиля
(`page_size`) и по лимиту одного USB-пакета CH341A:

- запись — не более 28 байт полезной нагрузки на пакет;
- чтение — не более 29 байт на пакет.

После каждой страницы выдерживается пауза `write_cycle_ms` (минимум 2 мс).
`ChipWorker` перед записью читает чип, сравнивает блоки и пропускает
неизменённые, затем выполняет верификацию.

## Тесты

| Тест | Что проверяет |
|------|----------------|
| `test_checksum` | CRC32 на известных векторах |
| `test_dump` | сохранение/загрузка контейнера, сравнение дампов |
| `test_profile` | разбор JSON, загрузка встроенных профилей |
| `test_validation` | размеры, защищённые диапазоны, разрешённые изменения |
| `test_hexeditor` | разбор и обратная сборка HEX-строк (QtWidgets) |

Тесты запускаются через `ctest` с `QT_QPA_PLATFORM=offscreen`.
