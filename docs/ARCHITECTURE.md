# Архитектура

## Обзор

Приложение разделено на независимое ядро и графический интерфейс.
Ядро (`Resetter_core`) собирается как статическая библиотека и не зависит
от QtWidgets, поэтому его можно использовать в тестах и консольных утилитах.

```
┌──────────────────────────────────────────────────────────────┐
│ gui/         MainWindow, ConnectionPanel, CartridgePanel,    │
│              OperationsPanel, HexEditor, LogPanel, StatusBar │
└───────────────▲───────────────────────────┬──────────────────┘
                │ сигналы/слоты Qt          │ запросы операций
┌───────────────┴───────────────────────────▼──────────────────┐
│ core/        ChipWorker (рабочий поток), ProfileManager,     │
│              DumpManager, CounterReset, Validator, Checksum  │
└───────────────▲───────────────────────────┬──────────────────┘
                │ ChipParams                │ read/write/scan
┌───────────────┴───────────────────────────▼──────────────────┐
│ adapters/    AdapterFactory, IChipAdapter                    │
│              Ch341Protocol + Ch341AI2cAdapter (libusb)       │
│              SerialProtocol + SerialI2cAdapter (termios)     │
└──────────────────────────────────────────────────────────────┘
```

## Потоки выполнения

- **GUI-поток** — все виджеты, HEX-редактор и журнал.
- **Рабочий поток** — `ChipWorker`, созданный в `MainWindow::setupWorker()`
  и перенесённый в `QThread`. Длительные операции (чтение, запись,
  верификация, сканирование) выполняются здесь.
- Обмен результатами — через сигналы `operationResult`, `operationProgress`,
  `operationFinished` с `Qt::QueuedConnection`.
- Отмена — атомарный флаг `ChipWorker::cancel()`, безопасный из GUI-потока.
- При завершении приложения поток останавливается, а `ChipWorker` удаляется
  через `QThread::finished → deleteLater`.

## Адаптеры

`AdapterFactory` разбирает строку спецификации:

| Спецификация | Адаптер |
|--------------|---------|
| `ch341a` | CH341A с автоопределением PID |
| `ch341a:1A86:5512` | CH341A-совместимая плата с явным VID/PID |
| `serial:/dev/ttyUSB0` | самодельный последовательный адаптер |
| `serial:` | он же с автопоиском порта |

Чистые функции сборки пакетов (`Ch341Protocol`, `SerialProtocol`) вынесены
из адаптеров и покрыты тестами без оборудования.

## Профили

`ProfileManager` — синглтон, загружающий `*.json` из каталога профилей.
Один файл может содержать массив профилей или один объект. Профили чипов и
картриджей различаются наличием поля `chip_profile`.

Каталог ищется в порядке:

1. переменная окружения `RESETTER_CHIP_PROFILES`
   (старое имя `Resetter_CHIP_PROFILES`);
2. `./profiles` рядом с исполняемым файлом;
3. `../share/resetter-chip/profiles` и `../../share/resetter-chip/profiles`;
4. исходники (`../src/profiles`, `../../src/profiles`);
5. `/usr/share/resetter-chip/profiles`, `/usr/local/share/...`;
6. старые пути с `Resetter-chip` для совместимости.

`resolveProfile()` превращает профиль картриджа в `ChipProfile`:
подставляет базовый чип, переопределяет смещение счётчика, защищённые
и разрешённые зоны. Некорректные переопределения отвергаются.

## Контейнер дампа

`DumpManager` сохраняет данные в собственный формат `RSCHIPD1`:

```
+--------+----------------+------------------+-----------+-------+
| 8 байт |  quint16       |  QString id      |  QString  | QDateTime |
| magic  |  версия = 1    |  чипа/профиля    |  картридж |  время    |
+--------+----------------+------------------+-----------+-------+
| quint32 размер | quint32 CRC32 |  данные (raw)                    |
+---------------------------------------------------------------+
```

Метаданные пишутся через `QDataStream` версии `Qt_6_0`. При загрузке:

- файл с магией разбирается как контейнер;
- повреждённый контейнер **отвергается**, а не трактуется как сырой дамп;
- CRC32 проверяется заново и попадает в `DumpInfo`;
- файл без магии считается сырым бинарным дампом `.bin`.

Запись файлов выполняется через `QSaveFile` — атомарно, без недописанных
дампов при обрыве питания.

## Сброс счётчика

`CounterReset` работает только с дампом в памяти:

- `readCounter()` — читает `counterSize` байт (1, 2 или 4) по `counterOffset`;
- `resetCounter()` — возвращает копию дампа с обнулённым счётчиком;
- `setCounter()` — записывает произвольное значение с проверкой границ;
- порядок байт — явный little-endian.

Смещение `0xFFFFFFFF` означает, что счётчик для профиля не задан.
В профилях чипов `24Cxx` счётчик не задаётся: он зависит от картриджа,
поэтому его определяет профиль картриджа.

## Валидация перед записью

`ChipWorker` перед записью читает текущее содержимое чипа и вызывает
`Validator::validateBeforeWrite()`:

1. размер дампа совпадает с `size_bytes` профиля;
2. изменения не затрагивают `protected_ranges` (пары `[start, end)`);
3. изменённые байты лежат в `allowed_modify_ranges`, если список задан.

При нарушении запись блокируется, а причина попадает в журнал.

## Запись, резервная копия и верификация

`ChipWorker::requestWrite()`:

1. читает исходный дамп чипа;
2. проверяет защищённые и разрешённые зоны;
3. если изменений нет — завершает операцию без записи;
4. сохраняет автоматическую резервную копию в каталог резервных копий;
5. записывает только изменённые блоки (по страницам профиля);
6. автоматически читает чип и сравнивает результат с целевым дампом;
7. возвращает путь резервной копии и список различий при ошибке.

Адаптеры дополнительно разбивают данные по лимитам транспорта:

- CH341A: не более 28 байт полезной нагрузки на USB-пакет при записи и
  29 байт при чтении;
- последовательный адаптер: не более 32 байт на I2C-транзакцию.

После каждой страницы выдерживается пауза `write_cycle_ms` (минимум 2 мс)
и выполняется ACK-опрос готовности EEPROM.

## Тесты

| Тест | Что проверяет |
|------|----------------|
| `test_checksum` | CRC32 на известных векторах |
| `test_dump` | контейнер, CRC, отказ от повреждённых файлов, сырые дампы |
| `test_profile` | разбор JSON, профили чипов и картриджей |
| `test_validation` | размеры, защищённые/разрешённые диапазоны, счётчик |
| `test_protocol` | пакеты CH341A и кадры последовательного протокола |
| `test_hexeditor` | разбор, сборка, поиск и заполнение HEX-строк (QtWidgets) |

Тесты запускаются через `ctest` с `QT_QPA_PLATFORM=offscreen`.
