# Протокол CH341A (режим I2C)

Реализация — `src/adapters/Ch341AI2cAdapter.cpp`.

## USB

| Параметр | Значение |
|----------|----------|
| VID / PID | `0x1A86` / `0x5512` (в udev-правиле также `5523`, `5535`, `5572`) |
| Интерфейс | 0, захватывается через libusb |
| Bulk OUT | `0x02` |
| Bulk IN | `0x82` |
| Таймаут передачи | 1000 мс |
| Скорость I2C | 100 кГц (команда `0x61`) |

При открытии устройство переводится в режим I2C потоковой командой:

```
AA 61 00
```

## Пакет «I2C stream»

| Байт | Назначение |
|------|------------|
| `0xAA` | ведущая команда режима I2C |
| `0x74` | START |
| `0x75` | STOP |
| `0x80 \| n` | записать `n` байт (1…63) |
| `0xC0 \| (n-1)` | прочитать `n` байт (1…64) |
| `0x60 \| speed` | скорость шины: 0 — 20 кГц, 1 — 100 кГц, 2 — 400 кГц, 3 — 750 кГц |
| `0x00` | конец пакета |

Ответ устройства начинается байтом статуса. Бит `0x80` означает NAK
(чип не подтвердил транзакцию); такие операции считаются ошибкой.

## Чтение

Пакет выполняет «dummy write» адреса памяти, затем повторный START
и чтение нужного количества байт:

```
AA 74 (80|A) [адрес памяти] 74 (80|1) [адрес устройства | 0x01] (C0|(n-1)) 75 00
```

- `A` — 1 байт для `24C01…24C16`, 2 байта для `24C32` и крупнее;
- адрес устройства — `(0x50 << 1) | (block << 1) | 0x01`;
- `block` — старшие биты адреса для `24C04` (1 бит), `24C08` (2), `24C16` (3);
- за один пакет читается не более 29 байт.

## Запись

```
AA 74 (80|N) [адрес устройства] [адрес памяти] [данные] 75 00
```

- `N` = размер адреса памяти + длина данных, но не более 28 байт;
- запись не пересекает границу страницы `page_size` из профиля;
- после страницы выдерживается пауза `write_cycle_ms` (минимум 2 мс) —
  внутренний цикл записи EEPROM.

## Сканирование шины

Для каждого адреса `0x08…0x77` отправляется пробный пакет:

```
AA 74 (80|1) [адрес << 1] 75 00
```

Устройство считается найденным, если транзакция завершилась без NAK.

## Ограничения и проверка

- Протокол реализован по документации CH341A и логике открытых реализаций.
- **Проверка на физическом программаторе не выполнялась** — в среде разработки
  не было оборудования. Перед работой с боевыми картриджами протестируйте
  чтение/запись на эталонном чипе.
- При ошибках USB или NAK возвращается текстовая причина через
  `lastError()`, она попадает в журнал приложения.
- Доступ без `root` обеспечивает udev-правило `packaging/99-ch341a.rules`
  (режим `0666`, группа `plugdev`).
