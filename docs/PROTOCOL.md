# Протоколы программаторов

Приложение поддерживает два семейства адаптеров:

- CH341A (и совместимые платы) через libusb — раздел [CH341A](#ch341a-режим-i2c);
- самодельный программатор на Arduino/ESP через последовательный порт —
  раздел [Последовательный DIY-адаптер](#последовательный-diy-адаптер).

## CH341A (режим I2C)

Реализация — `src/adapters/Ch341Protocol.cpp` и `src/adapters/Ch341AI2cAdapter.cpp`.

### USB

| Параметр | Значение |
|----------|----------|
| VID / PID | `0x1A86` / `0x5512` (также `5523`, `5535`, `5572`) |
| Свой VID/PID | спецификация `ch341a:VID:PID`, hex |
| Интерфейс | 0, захватывается через libusb |
| Bulk OUT | `0x02` |
| Bulk IN | `0x82` |
| Таймаут передачи | 1000 мс |
| Скорость I2C | 100 кГц (команда `0x61`) |

При открытии устройство переводится в режим I2C потоковой командой:

```
AA 61 00
```

### Пакет «I2C stream»

| Байт | Назначение |
|------|------------|
| `0xAA` | ведущая команда режима I2C |
| `0x74` | START |
| `0x75` | STOP |
| `0x80 \| n` | записать `n` байт (1…63) |
| `0xC0 \| (n-1)` | прочитать `n` байт (1…64) |
| `0x60 \| speed` | скорость шины: 0 — 20 кГц, 1 — 100 кГц, 2 — 400 кГц, 3 — 750 кГц |
| `0x00` | конец пакета |

Ответ устройства начинается байтом статуса. Бит `0x80` означает NAK
(чип не подтвердил транзакцию); такие операции считаются ошибкой.

### Чтение

Пакет выполняет «dummy write» адреса памяти, затем повторный START
и чтение нужного количества байт:

```
AA 74 (80|A) [адрес устройства] [адрес памяти] 74 (80|1) [адрес устройства | 0x01] (C0|(n-1)) 75 00
```

- `A` — 1 байт для `24C01…24C16`, 2 байта для `24C32` и крупнее;
- адрес устройства — `(0x50 << 1) | (block << 1) | 0x01`;
- `block` — старшие биты адреса для `24C04` (1 бит), `24C08` (2),
  `24C16` (3), `24C1024` (1 бит из адреса bit 16);
- за один пакет читается не более 29 байт.

### Запись

```
AA 74 (80|N) [адрес устройства] [адрес памяти] [данные] 75 00
```

- `N` = размер адреса памяти + длина данных, но не более 28 байт;
- запись не пересекает границу страницы `page_size` из профиля;
- после страницы выдерживается пауза `write_cycle_ms` (минимум 2 мс)
  и ACK-опрос готовности EEPROM.

### Сканирование шины

Для каждого адреса `0x08…0x77` отправляется пробный пакет:

```
AA 74 (80|1) [адрес << 1] 75 00
```

Устройство считается найденным, если транзакция завершилась без NAK.

### Ограничения и проверка

- Протокол реализован по документации CH341A и логике открытых реализаций.
- **Проверка на физическом программаторе не выполнялась** — в среде разработки
  не было оборудования. Перед работой с боевыми картриджами протестируйте
  чтение/запись на эталонном чипе.
- При ошибках USB или NAK возвращается текстовая причина через
  `lastError()`, она попадает в журнал приложения.
- Доступ без `root` обеспечивает udev-правило `packaging/99-ch341a.rules`
  (режим `0666`, группа `plugdev`).

## Последовательный DIY-адаптер

Реализация — `src/adapters/SerialProtocol.cpp` и `src/adapters/SerialI2cAdapter.cpp`.
Прошивка — [`firmware/resetter-serial-i2c/resetter-serial-i2c.ino`](../firmware/resetter-serial-i2c/resetter-serial-i2c.ino).

### Параметры порта

| Параметр | Значение |
|----------|----------|
| Скорость | 115200 бит/с |
| Формат | 8N1, без управления потоком |
| Порт | задаётся в UI или автоматически (`/dev/ttyUSB0`, `/dev/ttyACM0`, `/dev/serial0`) |
| Спецификация | `serial:/dev/ttyUSB0`, `serial:` — автопоиск |

### Кадр запроса

```
A5 5A | cmd(1) | i2c_addr(1) | mem_addr(4, LE) | length(2, LE) | payload | CRC16(2, LE)
```

CRC16 — сумма всех байт от `cmd` до конца payload, младший байт первым.

| Команда | Код | Назначение |
|---------|-----|------------|
| `Read` | 1 | Прочитать `length` байт; payload пуст |
| `Write` | 2 | Записать payload по адресу; `length` = размер payload |
| `Scan` | 3 | Просканировать шину, ответ — список 7-битных адресов |
| `Ping` | 4 | Проверка связи, ответ начинается с `RESETTER` |
| `Configure` | 5 | Передать геометрию чипа (payload 7 байт) |

Payload команды `Configure`:

```
deviceAddress(1) | twoByteAddress(1) | blockBits(1) | pageSize(2, LE) | writeCycleMs(2, LE)
```

### Кадр ответа

```
A5 5A | status(1) | cmd(1) | length(2, LE) | payload | CRC16(2, LE)
```

| Статус | Код | Значение |
|--------|-----|----------|
| `Ok` | 0 | Успешно |
| `Nak` | 1 | Чип не подтвердил транзакцию |
| `BadRequest` | 2 | Неверная команда или длина |
| `BusError` | 3 | Ошибка шины I2C |
| `Unsupported` | 4 | Команда не поддерживается прошивкой |

### Обработка адресации в прошивке

Прошивка получает `i2c_addr`, `mem_addr` и `Configure`, сама вычисляет
7-битный адрес для библиотеки `Wire`:

```
device7 = i2c_addr | block
block   = (mem_addr >> 8) & ((1 << blockBits) - 1)   // 24C04/08/16
block   = (mem_addr >> 16) & ((1 << blockBits) - 1)  // 24C1024 и крупнее
```

Библиотека `Wire` сама сдвигает 7-битный адрес влево и добавляет бит
чтения/записи, поэтому передавать ей готовый байт `(addr << 1)` нельзя.

Адрес памяти передаётся одним байтом для `24C01…24C16` и двумя байтами
(старший первым) для `24C32` и крупнее. Прошивка также не пересекает границу
страницы и опрашивает ACK после записи.

### Подключение

| EEPROM | Arduino Uno/Nano | ESP8266 | ESP32 |
|--------|------------------|---------|-------|
| SDA | A4 | GPIO4 | GPIO21 |
| SCL | A5 | GPIO5 | GPIO22 |
| GND | GND | GND | GND |
| VCC | 3.3/5 В | 3.3 В | 3.3 В |

SDA/SCL подтягиваются к питанию резисторами 4.7 кОм, если их нет на модуле.
Перед подключением чипа проверьте его рабочее напряжение по datasheet.

### Проверка связи

1. Прошейте плату скетчем из `firmware/resetter-serial-i2c`.
2. Подключите плату по USB и выберите адаптер «Самодельный Arduino/ESP».
3. Укажите порт или оставьте поле пустым.
4. Нажмите «Подключить программатор» — приложение отправит `Ping` и проверит
   ответ `RESETTER`.
